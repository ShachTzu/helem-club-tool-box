## 1. התשובה הקצרה

**כן, אפשר — אבל לא בחיבור ישיר.**

למונדיי אין "יציאה" ל‑MongoDB. אין קונקטור, אין אינטגרציה מוכנה, ואי אפשר לתת למונדיי
כתובת של מסד נתונים ולבקש שיכתוב לשם. מה שכן יש זה **API** ו‑**webhooks**, ודרכם אנחנו
מושכים את התשובות אלינו וכותבים אותן ל‑Mongo בעצמנו.

כלומר: הטופס ממשיך לחיות במונדיי, והשרת שלנו הוא זה שמושך משם ומכניס ל‑Mongo.

**מה צריך כדי שזה יעבוד — שני דברים שאני לא יכול להשיג לבד:**

1. **טוקן API של מונדיי** לחשבון שבו יושב הלוח (מי שאדמין בחשבון: פרופיל → Developers
   → My access tokens). הטוקן נשמר כמשתנה סביבה `MONDAY_API_TOKEN` — לא בקוד, לא בדפדפן.
2. **מזהה הלוח (board id)** שאליו הטופס כותב. מקבלים אותו בשאילתה אחת מול ה‑API אחרי
   שיש טוקן.

בלי אלה אפשר לכתוב את הקוד אבל לא להריץ אותו.

## 2. שלוש דרכים, לפי סדר העדפה

### א. Webhook — מונדיי דוחף אלינו (מומלץ)

באוטומציות של הלוח: `when an item is created → send a webhook to URL`.
מונדיי שולח POST לכתובת שלנו בכל תשובה חדשה, אנחנו כותבים ל‑Mongo מיד.

- **יתרון:** בזמן אמת, בלי פולינג, בלי לפספס.
- **חסרון:** צריך endpoint ציבורי, וצריך לטפל ב‑handshake של מונדיי (ראו §5).

### ב. Polling — אנחנו מושכים ממונדיי

קרון כל X דקות, שאילתת GraphQL של `items_page` על הלוח, upsert לכל פריט.

- **יתרון:** לא צריך endpoint ציבורי, עמיד לתקלות רשת (הריצה הבאה תשלים).
- **חסרון:** לא בזמן אמת, ומבזבז קריאות API.

### ג. ייצוא CSV — לתשובות שכבר נאספו

בלוח: `Export board to Excel`, ואז סקריפט חד‑פעמי שמייבא ל‑Mongo.
זו הדרך הנכונה ל**מלאי הקיים**, לא לזרם המתמשך.

**ההמלצה שלי:** ג' פעם אחת עבור מה שכבר נאסף, ואז א' לזרם החדש —
ורק עד שהאונבורדינג באתר (תוצר 2) עולה לאוויר. מרגע שהוא באוויר, האתר הוא מקור האמת
ולא צריך את הטופס בכלל. שני מקורות במקביל לאותם נתונים = באג שמחכה לקרות.

חילצתי אותם מהטופס עצמו. אלה בדיוק המפתחות שיחזרו מ‑`column_values` ב‑API:

| # | שאלה | column id | סוג במונדיי | שדה מוצע ב‑Mongo |
|---|------|-----------|-------------|-------------------|
| 1 | שם מלא | `name` | Name | `fullName` |
| 2 | מספר טלפון **(חובה)** | `phone_mm3pxef8` | Phone | `phone` |
| 3 | כתובת מייל | `email_mm3ps6ta` | Email | `contactEmail` |
| 4 | גיל | `number4oqnvcvi` | Number | `age` |
| 5 | כתובת | `locationikifxxn4` | Location | `city` |
| 6 | תפקיד/ים בתוך הקהילה | `text_mm456aqn` | ShortText | `communityRoles` |
| 7 | מגדר | `color_mm45tx6h` | SingleSelect | `gender` |
| 8 | הפציעה שלך בכמה מילים | `text_mm45khhm` | ShortText | `injuryNote` ⚠️ |
| 9 | הכרה בביטוח לאומי / משרד הביטחון | `color_mm46j878` | SingleSelect | `recognitionStatus` ⚠️ |
| 10 | מקצוע | `text_mm45wtsc` | ShortText | `profession` |

### ערכי הבחירה (מונדיי מחזיר אינדקס, לא טקסט)

**מגדר** (`color_mm45tx6h`): `0` = נקבה · `1` = זכר · `3` = אחר
*(שימו לב: אין `2` — מחקו אופציה בעבר. אל תניחו רצף.)*

**הכרה** (`color_mm46j878`): `1` = יש לי הכרה · `0` = אני בתהליך להכרה ·
`2` = בכוונתי לעשות בעתיד · `3` = אין לי וגם לא אעשה
*(גם כאן הסדר לא לפי המספרים — חובה למפות לפי הטבלה ולא לפי המיקום.)*

## 4. שאילתת ה‑API והכתיבה ל‑Mongo

```graphql
query ($boardId: ID!, $cursor: String) {
  boards(ids: [$boardId]) {
    items_page(limit: 100, cursor: $cursor) {
      cursor
      items {
        id
        created_at
        column_values { id text value }
      }
    }
  }
}
```

- קוראים ל‑`https://api.monday.com/v2` עם `Authorization: <MONDAY_API_TOKEN>`
  ו‑`API-Version: 2024-10` (או חדש יותר).
- `text` = הערך המוצג. `value` = JSON גולמי — משם לוקחים את האינדקס של הבחירות.
- ממשיכים עם ה‑`cursor` עד שהוא חוזר `null`.

**כתיבה ל‑Mongo — upsert, לא insert:**

```js
await MemberProfileModel.updateOne(
  { mondayItemId: item.id },        // אינדקס unique על השדה הזה
  { $set: mapped },
  { upsert: true }
);
```

זה מה שהופך את זה לבטוח: אפשר להריץ את הייבוא שוב ושוב בלי לשכפל אף שורה, וזה גם
מכסה את המקרה ש‑webhook נשלח פעמיים (מונדיי עושה את זה כשיש timeout).

## 5. שני דברים שחייבים לזכור

**ה‑handshake של ה‑webhook.** בפעם הראשונה מונדיי שולח `{"challenge": "..."}`
וה‑endpoint חייב להחזיר את אותו ערך בדיוק, אחרת ההרשמה נכשלת:

```js
if (req.body.challenge) return res.json({ challenge: req.body.challenge });
```

**ה‑endpoint פתוח לעולם.** מונדיי לא חותם את הבקשות בצורה שאפשר לסמוך עליה, אז
מוסיפים סוד משלנו לכתובת (`/webhooks/monday/<MONDAY_WEBHOOK_SECRET>`) ומשווים אותו
בצד שרת לפני שנוגעים בגוף הבקשה. בלי זה כל אחד באינטרנט יכול להזריק "חברי קהילה".

## 6. פרטיות — זה לא סעיף פורמלי

הטופס אוסף **טלפון, כתובת מגורים, תיאור פציעה ומצב הכרה בביטוח לאומי**.
פציעה והכרה הם **מידע רפואי** — מידע רגיש לפי חוק הגנת הפרטיות, לא "עוד שדה".

לכן, מה שחייב להתקיים בכל אחת מהדרכים למעלה:

- אוסף (collection) **נפרד** משאר המשתמשים, לא שדות על רשומת המשתמש הציבורית.
- אף שדה מ‑8 ו‑9 לא נכנס לשום טיפוס GraphQL ציבורי. גישה = אדמין בלבד, בבדיקה בצד שרת.
- הטוקן והסוד רק במשתני סביבה. אף פעם לא בבנדל של הדפדפן ולא בגיט.
- לא לוגים של גוף הבקשה. שורת לוג אחת עם מזהה פריט מספיקה לדיבוג.
- מי שממלא צריך לדעת לאן זה הולך — משפט אחד בתחתית הטופס, ואותו משפט באונבורדינג באתר.

זו בדיוק הסיבה שבתוצר 2 בניתי את פרופיל החבר כאוסף נפרד עם הרשאת אדמין, ולא כשדות
על המשתמש.

## 7. מה צריך ממך כדי להתקדם

1. טוקן API של מונדיי בסביבה שבה האפליקציה רצה (`MONDAY_API_TOKEN`) — לא להדביק לי אותו.
2. אישור מרואי/יערית שמותר למשוך את התשובות הקיימות.
3. החלטה: ייבוא חד‑פעמי בלבד (ואז האתר הוא מקור האמת), או סנכרון מתמשך.

עם 1 ו‑2 אני כותב את סקריפט הייבוא והמיפוי בקומיט אחד. בלי 1 אי אפשר להריץ כלום.
